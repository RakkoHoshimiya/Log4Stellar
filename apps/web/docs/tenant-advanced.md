# 托管租户高级管理

## 租户双因素

租户管理员在「租户管理」的「租户安全」中启用或关闭策略。更改策略需要该会话先在「账户安全」完成绑定，或重新登录并完成 TOTP 或恢复码验证。变更写入租户审计，旧会话即使属于已绑定双因素的账号也无法访问受保护租户。绑定、挑战兑换和密码更新会保存或延续会话的验证凭证，过期、注销和撤销会话会移除凭证。

策略拦截工作台、挂载文件、搜索、同步、Git、Office 预览及租户管理数据接口。无法访问的工作区不出现在工作区列表中。账号安全设置仍可访问，便于完成验证。

## 独立桶

运营侧准备空桶和仅有该桶所需权限的访问凭据，把现有受保护存储配置中的 `tenantStorage` 配置为按租户 ID 关联 S3 设置。每项使用与默认 `s3` 相同的字段 `endpoint`、`region`、`bucket`、`accessKeyId` 和 `secretAccessKey`。不同租户配置必须使用不同的桶，启动时检查。Web 管理界面无需接触这些凭据。

先创建空租户、配置桶并重启服务，再建立工作区。对已经有文件的租户直接修改桶将改变读写位置。需要先完成对象复制和校验，或使用下节流程迁入新租户。保留并备份当前配置，备份会在清单中记录不含凭据的桶身份；恢复时为目标环境提供独立的默认桶及租户配置。清理器也按租户选桶，沿用全局物理删除开关。

## 跨租户工作区迁移

该操作由服务器运维执行。准备源租户和目标租户的管理员账号 ID、工作区 ID、两个租户 ID，以及一次迁移专用 UUID。先完成可恢复的全量备份。安排维护窗口，停止所有持有旧工作区连接的 Web 进程、旧版本的后台备份和清理命令。新版 Web、备份和清理命令通过数据库维护锁与迁移互斥。

在仓库根目录运行以下命令预检，确认返回的对象数量与工作区相符。待两边管理员确认后在同一条命令末尾加 `--apply` 执行，用同一 UUID 重试可识别已提交的迁移。凭据由主机环境中的受保护配置提供。

```sh
node apps/web/workspace-move.mjs WORKSPACE_ID SOURCE_TENANT_ID TARGET_TENANT_ID SOURCE_ADMIN_ID TARGET_ADMIN_ID MOVE_UUID
```

命令复制保留版本、有效快照和同步保留期内引用的对象，并回读校验 SHA-256。任一对象复制或校验失败时，映射和权限仍属于源租户。成功后一次性提交租户映射、目标所有者和两边的审计，工作区 ID 及文件版本维持原样。源租户的工作区授权会撤销，目标管理员按需重新授权。现有 Git 绑定、凭据或检查点需要先按原租户流程处理，迁移命令发现这些数据时会拒绝。

恢复服务后，由两边管理员核对拒绝和读取状态，并复验历史版本。源对象保留。若需回迁，先备份，交换两边的参数并使用新 UUID 完成反向迁移，按原权限记录重新分配授权。旧发布包无法理解独立桶和租户强制双因素策略。需要应用回退时先隔离受影响工作区，并按备份与权限方案恢复。
