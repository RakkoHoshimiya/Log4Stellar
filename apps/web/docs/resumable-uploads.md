# Web 附件断点续传

在资源管理器点「上传附件」，或右键目标文件夹选择同名命令。上传页支持查看进度、暂停和取消。刷新、断网或登录过期后，回到上传页重新选择同一个文件，再点「上传或续传」。服务端以已确认的分块为续传边界，浏览器逐块校验本地前缀。目标已有同名文件时另存冲突副本，上传页显示实际保存路径。

每块 8 MiB，总大小沿用 `LOG4STELLAR_MAX_UPLOAD_BYTES`，默认 512 MiB。每个账户每个工作区可同时保存两项待提交上传。分块和收据按账户与工作区存储，24 小时未写入后过期，后台按小时回收。暂存目录在存储配置旁的 `resumable-uploads`，应放在 Web 服务可写的持久卷。提交时还需为工作区对象写入准备暂存空间，服务器在空间不足时返回错误。该流程适用于共享工作区的 RustFS 后端。

## 路由与提交

- `PUT /api/v1/uploads/<uuid>` 创建或恢复会话，保存目标路径与大小。
- `GET /api/v1/uploads/<uuid>` 返回已确认偏移、分块哈希和可用收据。
- `PATCH /api/v1/uploads/<uuid>?offset=<bytes>` 接收一个完整分块。分块流校验成功后原子替换文件并更新偏移。短写、超长、错误偏移均保留此前确认状态。
- `POST /api/v1/uploads/<uuid>/complete` 重新校验分块，写入对象与版本。完成结果可重复读取，已发布后的重复请求重用同一版本。
- `DELETE /api/v1/uploads/<uuid>` 取消尚未提交的暂存。若已开始保存而结果未知，用续传确认最终结果。

服务端在工作区写权限检查之后读取请求体。每个账户与工作区的 PostgreSQL 锁串行化暂存变更。文件版本提交复用持久化幂等记录，覆盖提交成功但暂存收据来不及保存的失败窗口。

## 验收

默认测试校验上传页的语言和路径转义。PostgreSQL 用例需独立环回库 `managed_acceptance`。

```sh
LOG4STELLAR_UPLOAD_IT=1 node --test apps/web/resumable-uploads.test.mjs
```

浏览器验收用十几 MiB 文件触发三个分块，中断第二块后刷新页面。重新选择同名同大小但内容不同的文件应被拒绝，选择原文件应从已确认的偏移续传。校验 RustFS 回读 SHA-256、版本数量和重复完成响应，另验暂停、取消、越权工作区拒绝、超限与损坏分块。
